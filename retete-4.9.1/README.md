# Cartea mea de retete

Aplicatie personala pentru retete: le gasesti, le adaptezi, le planifici si faci lista de cumparaturi, plus tabele de nutritie si masuri. Fara server si fara build. Publicata pe GitHub Pages. Datele tale raman in browser; nimic nu se trimite nicaieri in afara de cererile catre Anthropic, facute doar cand apesi un buton.

Date (de la 4.0.0): retetele salvate au un id stabil (`id`); cheia lor in favorite, jurnal, meniu si Meal prep este `salvat|<id>` (`sKey`), iar a retetelor din carti ramane `sursa|nr` (`bKey`). `sidRun` aduce la acest format datele vechi (pornire, restaurare, sincronizare). Tintele de macro vin doar din `rprof`; `rmt` nu se mai foloseste.

Carti livrate (de la 4.1.0): `carti.json` listeaza cartile (`sursa`, fisier, versiune `v`), iar retetele stau in `carti/*.json`. `shipRun` le instaleaza la pornire si le actualizeaza cand creste `v`; o reteta livrata are `liv` (versiunea) si `lh` (amprenta continutului), iar daca amprenta nu mai corespunde e considerata a utilizatorului: nu se suprascrie si intra in backup. Ca sa publici o corectie intr-o carte: modifici fisierul din `carti/` si cresti `v` in `carti.json`. Retetele noi primesc numere `nr` mai mari decat cele existente. Backup-ul contine retetele utilizatorului, cele schimbate de el si lista celor livrate (`rliv`).

Siguranta si robustete (de la 4.1.1): Content-Security-Policy in `index.html` (la o adresa noua apelata din cod, adaug-o la `connect-src`); tot ce vine din date trece prin `esc` inainte de a ajunge in pagina; butoanele din liste cauta randul dupa cheie (`data-lk`, `data-sk`), nu dupa pozitie; alt tab deschis e detectat prin evenimentul `storage` (`stApply`); cheile de date sunt intr-o singura lista (`DKEYS`). Depanare: `localStorage.rdebug = "1"` arata in consola erorile tratate in tacere. Teste (date inventate, fara backup real): `npm install jsdom`, apoi `node teste/test_cumparaturi_meniu_id.js`, `node teste/test_carti.js`, `node teste/test_4_1_1.js`, `node teste/test_4_2_0.js`, `node teste/test_4_3_0.js`, `node teste/test_4_3_1.js`, `node teste/test_4_3_2.js`, `node teste/test_4_4_0.js`, `node teste/test_4_5_0.js`, `node teste/test_4_6_0.js`, `node teste/test_4_7_0.js`, `node teste/test_4_7_1.js`, `node teste/test_4_8_0.js`, `node teste/test_4_8_1.js`, `test_4_9_0.js`.

## Ce face (pe sectiuni)
Navigare: bara cu 5 destinatii (Retete, Meniu, Cumparaturi, Debara, Mai mult): jos pe telefon (sub 700 px), sus pe ecran lat. Sub "Retete" sunt pilulele Idei / Biblioteca / Colectia mea; "Mai mult" duce la Ghid nutritie (Ingrediente, Masuri, Gatire) si la Setari. Cod: `GROUPS`, `syncNav` in `app.js`, `#gnav` in `style.css`.
- **Retete**
  - *Idei*: retete generate de AI din ce ai in casa, cu aparatele tale active, sau cautate pe web. Cere o cheie API; fara cheie pagina arata doar trimiterea catre Biblioteca. Cat timp debaraua e goala apare "Primul pas".
  - *Biblioteca*: cartile tale de retete (sursa fiecarei retete, adica cartea si numarul, apare sub titlu), cu cautare, filtre (carte, categorie, eticheta, stare: "De verificat" (ingrediente si text), "Portii de verificat", "Macro de verificat", "Fara semn de intrebare" - ce ai in debara, jurnal, preferinte), gruparea retetelor cu acelasi titlu intr-un singur card (exemplarul cel mai complet, cu "Mai e si in: ..." pentru celelalte), paginare ("Arata mai multe"), corectarea retetelor si jurnal (stele, "Am gatit", notite) pe fiecare reteta. Retetele se afiseaza fara diacritice.
  - *Colectia mea*: ce pastrezi, intr-o lista cu filtrele Toate / Favorite / Generate de AI / Scrise de mine si Cos. Etichetele retetei sunt pliate (si in Biblioteca), cu cele alese afisate pe linie. Mesajele scurte au chenar verde cand a reusit ceva si rosu cand nu a mers. In reteta deschisa, iconul de cos de langa Favorita (confirmi cu bifa, renunti cu X) ascunde reteta din cautare, meniu si propuneri, fara sa o stearga; din Cos o restaurezi sau o stergi definitiv (cu X / bifa si Anuleaza).
- **Meniu, Cumparaturi, Debara** (pagini separate pe bara)
  - *Meniu*: azi si maine sau saptamana, cu patru mese pe zi (Mic dejun, Pranz, Cina, Desert; `SLOTS`). In fiecare masa: "+" langa numele mesei adauga, "-" in fata alimentului il scoate (cu Anuleaza). Pe fiecare zi: macro (calorii, proteine, carbohidrati, grasimi) cu bare fata de tintele tale si cat mai ramane, plus un panou "Micronutrienti" (25 de nutrienti fata de valorile de referinta EFSA pentru adulti). Fiecare reteta din meniu conteaza o portie. "Propune-mi un meniu" (din Biblioteca, Debara, preferinte si Mese). "Am gatit" scrie in jurnalul retetei.
  - *Cumparaturi*: lista pe produse sau pe retete (cu sursa fiecarui produs), grupata pe categorii, cu bifare, "Am in debara" si ascunderea produselor din debara.
  - *Debara*: ce ai deja, pe categorii, cu marcaje (proaspat, congelat, uscat, conserva) la categoriile care le au bifate (implicit Legume, Carne, Fructe, Leguminoase; `DEFCATS`); un singur camp pentru cautare si adaugare. "Am terminat" trimite produsul inapoi in Cumparaturi.
- **Ghid nutritie** (sub Mai mult; fostul Info; date din `nutri.js`, fara legatura cu restul datelor)
  - *Ingrediente*: calorii, proteine, carbohidrati, grasimi, iar la atingere fibre, minerale si vitamine, pentru o cantitate la alegere; filtru pe grupa, sortare si cautare.
  - *Masuri*: cat cantareste o lingura, o lingurita sau o cana din alimentele care se masoara asa.
  - *Gatire*: sfaturi pentru cine invata sa gateasca, pe teme pliabile: tehnici de baza, metode pas cu pas, formule fara reteta (cu varianta vegetariana si cu carne), timpi si temperaturi, siguranta alimentara, congelare, inlocuiri si greseli, organizare si economie, gatit vegetarian.
  - Sursa: USDA National Nutrient Database for Standard Reference, versiunea 28 (domeniu public), plus drojdia inactiva dupa eticheta produsului.
- **Setari** (doua taburi, Administrare si Tehnic; un punct pe Tehnic arata ca cere atentie cheia sau backup-ul): Administrare: Profil nutritional (sex, varsta, greutate, inaltime, activitate, scop; din ele se calculeaza tintele zilnice de calorii si macro, pe care le poti edita; micronutrientii urmeaza standardul EFSA), Aparate, Preferinte alimente, Categorii alimente, Etichete retete (nume, tip bucatarie, dieta sau metoda si bifa "Afiseaza" ca sa ascunzi din filtre, carduri si idei etichetele care nu-ti folosesc; implicit: traditional romanesc, asiatic, vegan, vegetarian, high-protein, keto, gluten-free, meal-prep, air fryer, one pot; automate: high-protein, keto pe carbohidrati neti, gluten-free), Mese (la ce masa se potriveste fiecare categorie); apoi tabul Tehnic: Carti (carti livrate cu aplicatia, 856 de retete: Retete vegetariene (216), Retete cu carne (110), Deserturi rapide (30), Retete keto (200), Supe si ciorbe keto (300); incarcarea altor carti, corectiile, descarcarea si "Readu cartile aplicatiei"), Backup (in fisier, copii automate in browser, Dropbox), AI si cheie (cheia API, modele) si Despre (versiunea; istoricul modificarilor e pliat). Tasta Inapoi a telefonului merge pas cu pas (reteta, subpagina, pagina), fara sa iesi din aplicatie.

AI-ul (Anthropic) se foloseste doar cand apesi: idei, reteta completa, adaptare, estimare de macro si, optional, un meniu generat. Restul (cautare, meniu propus, liste, debara, Info) merge local si gratuit.

Corectarea unei retete (Mai multe actiuni > Corecteaza reteta): daca ingredientele sau pasii lipsesc pentru ca extragerea din carte a esuat, dar textul paginii e pastrat, casetele se completa din liniile detectate in text, ca sa le corectezi in loc sa scrii de la zero.

Cumparaturi: produsele se compara dupa `lkey` (singular/plural ignorat; de la 3.20.0 si felul in care e taiat, "de" de la inceput si locul cuvantului de masura, prin `lClean`; kg si l se aduc la g si ml) in `addList` si `listDedupe`; sursa produsului e link (`data-lsrc`) catre reteta, cautata dupa titlu. Meal prep (Meniu; se adauga si din orice reteta deschisa, buton `data-mpr`, `mpBtn`; pe lot: `mpInMen`): `rmp` = [{id,s,k,t,d,p}] (reteta gatita in lot, data, portii informative); `mpHtml`, `mpOpen`, `mpForm`, `mpSave`; la adaugarea unui lot, mesele de azi inainte cu aceeasi reteta primesc `en.mp=1`, la fel orice masa adaugata (`menAdd`) cu reteta unui lot activ; caseta de cumparaturi din formular apare mereu cand e ceva de cumparat (produsele ascunse, pe care le ai in debara, nu conteaza in `inCartAny`); daca reteta e deja in lista, bifa actualizeaza cantitatile; daca ai tot in debara, apare doar mesajul; mesele cu `en.mp=1` (fara "Am gatit", fara ingrediente in cumparaturile meniului). Nimic nu scade automat; "Terminat" scoate lotul.

Ecranul retetei (`renderRecipe` pentru generate/salvate/adaptate, `openBook` pentru carti) are aceeasi ordine: titlu, actiuni, Ingrediente cu scalare (`BSC`, `data-bsc`, cheia `sKey`/`bKey`), Mod de preparare, Macro + Micronutrienti, Etichete, Jurnal. La generate/salvate macro si micro se calculeaza live din Info (`rcNut`, `macLocal`, `micHead`), fara AI si fara salvare. In Mod de preparare: `mode` = pasi (implicit; lista numerotata, aparat ca eticheta mica, "Start / dupa N min" si "in paralel" doar la pasi paraleli) / ap (Pe aparat). Retetele cu `din_carte` au sectiunea pliata "Pasii originali din carte". Previzualizarea adaptarii (`RC[...].bi`) nu repeta scalarea si macro-ul.

Marcaj AI: orice buton care cheama modelul (costa tokeni) are `data-ai="1"` si primeste un chip "✦ AI" din CSS; cand adaugi un apel `ask(...)` nou, marcheaza-i butonul (testul `test_marcaj_ai_si_cumparaturi.py` numara apelurile). Cumparaturi: butonul retetei e comutator (`cumBtn`, `cartToggle`, `cartRemove`, dupa titlul retetei). Macro in Meniu (`menMac`, `menLocal`): macro-ul retetei, apoi cel estimat cu AI din intrarea de meniu, apoi calculul din Info (>= 80% din ingrediente recunoscute); AI doar pentru restul. Cronologia arata timpul de start doar cand exista pasi in paralel.

Scalare la gatit: in reteta deschisa, sub Ingrediente, "Gatesc pentru [-] N [+] portii" scaleaza cantitatile din lista (`BSC`, `sclHtml`, `ingHtml(r,f)`, `ingBook(r,f)`) si le trimite scalate in Mod gatit; nu se salveaza si nu atinge portiile, macro-ul sau timpii; nu scaleaza numerele din textul pasilor. Fara numar de portii nu se poate scala.

Portii: in reteta deschisa, campul "Portii (reteta)" arata macro la numarul scris (fara sa schimbe cantitatile) si butonul "Salveaza N portii" il salveaza direct si recalculeaza macro-ul calculat local; campul exista pe toate retetele, si pe cele fara numar de portii (gol); numarul se mai poate confirma si in editor ("Confirma numarul de portii"); "-" inseamna ca nu se aplica. Corectii in masa (portii, marcaje, titluri noi `titlu_nou`, stergeri definitive `sterge`, cu copie automata inainte) se aplica din Setari > Carti, "Aplica un fisier de corectii", fara sa inlocuiasca retetele.

Tinte si micronutrienti: din profil (formula Mifflin-St Jeor x nivel de activitate, ajustata dupa scop; proteine pe kg la alegere: 0,83 / 1,6 / 2,0 sau valoare proprie; grasimi 30% din calorii, restul carbohidrati). Barele au o singura culoare (verde); linia marcheaza 100%; terracotta apare doar peste tinta la limite (sodiu, grasimi saturate, zaharuri) si la calorii, carbohidrati si grasimi. Valorile de referinta pentru adulti (inclusiv magneziu, vitamina E, D, K si sodiu) au fost verificate pe sursele EFSA in 3.5.1; vitamina K are tinta fixa de 70 µg, nu dependenta de greutate.

Alimente adaugate de tine (Info > Ingrediente > Editeaza): poti schimba numele (nu poate repeta un nume existent); un aliment venit de la AI ramane marcat AI chiar daca il corectezi manual. Poti seta o unitate cu greutatea ei (ex: 1 cub = 4 g). In Info, randul arata valorile pe unitate ("pentru 1 cub (4 g)"), iar in retete "1 cub zahar" se calculeaza ca 4 g. Cu campul "Pentru ... g" schimbat din 100, lista foloseste cantitatea ceruta.

Macro pe reteta: butonul "Calculeaza din Info" / "Recalculeaza din Info" (in reteta deschisa, si in Corecteaza reteta, unde completeaza campurile de macro) calculeaza local din Info > Ingrediente. Ingredientele fara date le cauti cu AI sau le completezi manual; se salveaza local (cheia `rfd`, inclusa in backup) si apar in Info > Ingrediente, "Adaugate de tine". Greutatile pe bucata si cuvintele fara calorii sunt in `nutri.js` (`NUTRI.P`, `NUTRI.Z`).

## Backup si actualizari

Datele tale stau in browser (localStorage si IndexedDB), nu in fisierele aplicatiei. Incarcarea unei versiuni noi in repo nu le sterge, inclusiv cheia API (`rk`) ramane in browser.

Baza Info (`nutri.js`, 1145 alimente, valori la 100 g din USDA SR Legacy 2018 si Release 28, domeniu public): randurile `R` (nume romanesc, grupa, stare, 27 de coloane), masurile `M`, greutati pe bucata `P`, cuvinte fara aport caloric `Z`, denumirile USDA in engleza `E` (aliniate cu `R`). Potrivirea ingredientelor (`fdMatch`) compara cuvinte-radacina: aliment gasit daca toate cuvintele lui sunt in ingredient; castiga cel mai lung. Starea de gatit (fiert/copt/prajit/gatit, cu sinonimele fiarta, fripta, la cuptor, la gratar...) e cuvant separat: alimentul gatit se alege doar daca ingredientul o spune. Un nume poate avea alias "(aprox. X)" sau "(sin. X)" (paranteza fara aceste prefixe e doar descriere si nu intra in potrivire). Cand adaugi alimente noi: nume fara diacritice, fara "crud" in nume, nume diferit de cele existente.

Marcaje de verificat (trei, separate): *De verificat* = ingrediente neclare sau rupte, text citit gresit (butonul "Parcurge retetele de verificat" trece doar prin ele; "Salveaza ca verificata" le sterge doar pe ele); *Portii de verificat* = numar de portii neconfirmat sau lipsa (dispare cand salvezi sau confirmi portiile); *Macro de verificat* = macro din carte nesigur (dispare cand il recalculezi din Info sau il corectezi si salvezi). In reteta deschisa, fiecare are avertismentul si culoarea lui.

**Backup complet** (Setari > Backup > Backup in fisier, "Descarca backup"): biblioteca intreaga cu toate retetele asa cum sunt (portii, `pna`, marcaje de verificat, etichete, text editat, macro), alimentele adaugate de tine (`rfd`, cu cei 27 de nutrienti si marca AI/manual), retete salvate, favorite, jurnal si notite, meniu, tinte de macro si profil nutritional (`rmt`, `rprof`), preferinte de alimente, mese pe categorie, definitiile etichetelor, aparate, debara, lista de cumparaturi, categoriile alimentelor, modelele AI alese. Nu include cheia API si datele de conectare Dropbox (intentionat) si nici datele Info din `nutri.js` (vin cu aplicatia). Se restaureaza din Setari > Backup, nu reincarcand fisierele cartilor.

**Copii automate** (Setari > Backup): in IndexedDB, ultimele 3, cel mult una la 20 de ore, plus una inainte de orice restaurare sau preluare din Dropbox.

**Sincronizare Dropbox** (Setari > Backup > Sincronizare Dropbox, de la 3.0.0): un singur fisier `sync.json` in folderul aplicatiei din Dropbox-ul fiecaruia. Aplicatia Dropbox (App key `7hvolba2cog2zy8`, cheie publica, fara secret, PKCE) e a proprietarului; fiecare utilizator doar apasa "Conecteaza Dropbox" o data pe fiecare dispozitiv si se logheaza cu contul lui. La sincronizare se combina in 3 pasi: starea de la ultima sincronizare (baza, in IndexedDB), starea de aici si cea din Dropbox. Ce s-a schimbat doar pe o parte se preia; modificarile pe elemente diferite se pastreaza amandoua; pe acelasi element castiga varianta de pe dispozitivul care sincronizeaza; modificarea bate stergerea. Se sincronizeaza tot ce intra in backup (inclusiv biblioteca si corectiile), nu cheia AI si nu cheile Dropbox. Frana: o sincronizare care ar sterge peste jumatate din biblioteca sau din retetele salvate se opreste si cere confirmare. La pornire datele noi se preiau singure si aplicatia se reincarca o data; in timpul folosirii apare o bara "Aplica acum". Pentru aplicatie Dropbox proprie: Setari > Backup > Sincronizare Dropbox > Avansat (Create app > Scoped access > App folder, permisiuni `files.metadata.read`, `files.content.read`, `files.content.write`, la "Redirect URIs" adresa afisata). Cheile `rdbk`, `rdbt`, `rdbl`, `rdbr`, `rdba` nu intra in backup. Fisierul `sync.json` are istoric de versiuni in Dropbox.

**Dubluri** (Setari > Carti, "Gaseste dubluri"): cauta retete care se repeta intre carti, dupa titlu si ingrediente (nu doar dupa nume). Arata lista pe perechi, cu copia pastrata (cea folosita in favorite/Meal prep/meniu/jurnal, apoi cea mai completa); poti debifa perechi si anula eliminarea. "Retetele mele" nu se ating.

**Backup per carte** (Setari > Carti, "Descarca JSON" langa carte): doar retetele acelei carti, cu tot ce e scris pe ele (portii, marcaje, macro, text editat). Nu include alimentele tale (`rfd`), favoritele, jurnalul, notitele, meniul sau preferintele. Reincarcarea lui inlocuieste cartea respectiva.

**Fisierul de corectii** (Setari > Carti, "Aplica un fisier de corectii"): aplica portii si marcaje pe retetele deja incarcate, fara sa le inlocuiasca. E un fisier privat, nu se pune in repo.

Sursa macro (campul `macro.sursa` pe reteta: `local` = calculat din Info, `ai` = estimat de AI, `manual` = scris de tine; fara camp pe o reteta scrisa de tine = "sursa necunoscuta"). Avertizare in Meniu: daca macro-ul din carte difera mult de calculul din Info, apare o nota sub reteta; "E in regula" o ascunde (campul `mok` pe reteta).

## Fisiere
- `index.html` - structura paginii (sectiuni, pagini, formulare)
- `style.css` - aspect (tema deschisa/inchisa prin variabile CSS)
- `app.js` - toata logica, cu sectiuni marcate `===== NUME =====`
- `nutri.js` - datele din Info (nutritie, masuri si sfaturile de gatire); se urca in repo la fiecare modificare
- `sw.js`, `manifest.webmanifest`, `icon-*.png` - instalare ca aplicatie si functionare fara net (se urca langa `index.html`)
- `CHANGELOG.md` - istoricul versiunilor (cel mai nou primul)
- `tests/` - teste automate cu Playwright (`test_*.py`, ajutor comun in `_h.py`)
- Cartile tale (fisiere JSON) NU intra in repo public: le incarci din Setari > Carti. `retete.json`, daca exista, este doar un exemplu. Fara nicio carte incarcata, aplicatia arata 6 retete demo originale (dispar cand incarci o carte sau scrii prima ta reteta).

## Cand modifici ceva
0. La fiecare pachet zip: versiunea (`APP_V`, `?v=`, `CHANGELOG.md`), README-ul (sectiunile Ce face, Backup, Fisiere), comentariul de la inceputul `app.js` si testele trebuie sa spuna acelasi lucru. `release.sh` verifica automat versiunea, cheile din `BK_KEYS` si paginile din Setari fata de README.
1. Schimba `APP_V` in `app.js` si numarul `?v=...` din `index.html` (pentru ca GitHub Pages sa nu serveasca fisiere vechi din cache).
2. Ruleaza testele, de exemplu `python tests/test_info.py` sau toate cu `for f in tests/test_*.py; do python $f; done`. Fiecare test afiseaza `OK`/`FAIL` si `probleme=N`; trebuie `probleme=0`.
3. Adauga o nota in `CHANGELOG.md` (versiunea noua sus).
4. Publica toate fisierele modificate, inclusiv `nutri.js` si `CHANGELOG.md` daca s-au schimbat.

## Reguli de cod
- Orice text din model sau din JSON trece prin `esc()` inainte de `innerHTML`; textul retetelor din carti se afiseaza prin `ed()` (`esc` fara diacritice).
- Biblioteca (cartile incarcate) sta in IndexedDB (`saveStored` / `getStored` / `STORED`); nu scrie direct `localStorage.rbook`.
- Datele noi in localStorage: adauga cheia in `BK_KEYS` (copia de siguranta) si in comentariul de la inceputul `app.js`.
- Cheia API nu intra niciodata in fisiere din repo; sta doar in localStorage (`rk`) si se trimite doar catre api.anthropic.com.
